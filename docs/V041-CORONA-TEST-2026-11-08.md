# Corona Phison Xbox 360 — hardware result, November 8 2026

Observed on real Corona Phison RGH hardware: starting via Eject shows the XeLL menu. The legacy v0.4 kernel boots Ubuntu Live/the installer, NOT the preinstalled Linux desktop. Earlier normal/debug kernel entries did not boot successfully. The old Aurora default.xex also black-screens.

## New experimental USB kernel (hardware result PENDING)

The historical 2011 vmlinux contains a 15,888,384-byte LZMA-compressed built-in initramfs with /init and Casper startup scripts. The new x360linux.elf retains the PowerPC ELF headers, instructions and image size but replaces only its built-in initramfs data with a 1,888,732-byte PowerPC32 initramfs. Its new LZMA stream is 754,200 bytes. Host ELF parsing, decompression checks, shell syntax and checksums passed. THIS DOES NOT prove the new kernel boots on Xbox hardware.

The root vmlinux and casper directory remain untouched as the known legacy fallback. The USB FAT32 disk E: contains a preinstalled 3-GiB ext4 Ubuntu system at distros/ubuntu-x360/rootfs.ext4. The prior USB boot files have been backed up and SHA256-verified on the Windows PC.

## English diagnostic boot menu in kboot.conf

0 - DIAGNOSTIC BOOT - SHOW ERRORS: experimental kernel with visible diagnostic output; now the default
1 - NORMAL BOOT - QUIET: experimental quiet boot; the November 8 hardware test resulted in a black screen
2 - LEGACY UBUNTU LIVE - INSTALLER: original legacy kernel, NOT the preinstalled Ubuntu system

The text XeLL Main Menu is part of XeLL. XeLL numbers menu options starting with zero. The system is NOT proven to reach the graphical Ubuntu desktop, and there is no verified Wi-Fi or Aurora XEX fix. No NAND files or Xbox internal HDD were altered.

## Automatic Eject boot on USB

The zero-second automatic configuration was prepared and backed up, but
the next USB configuration uses `timeout=25` for diagnosis. Option 0 is
now `DIAGNOSTIC BOOT - SHOW ERRORS` and is the default. The earlier
quiet option 0 was selected on real hardware and produced a black screen;
this is a confirmed failure symptom, not a successful desktop boot.

The upstream XeLL parser may print its English menu header. Removing that
screen would require modifying installed XeLL and remains out of scope.
The preinstalled ext4 Ubuntu desktop has NOT been confirmed on hardware.
